# LAN-21 情景对话首版

## 已确认需求（2026-10-19，替代旧版范围）

### 产品目标

本轮卡片练习结束后，用情景对话弹窗取代原总结报告体验，让学习者立即使用刚练过的表达。首版优先 Dialogue Agent，答疑 Agent 后置。

### 入口与范围

- 基于 staging 的新 Collection / Note / Card / Attempt / Review 模型，基线 `749a45f`。
- 本轮确实有已评分的 Attempt，且当前无可继续练的卡片时弹出场景窗口；首次进入空队列不触发，不代表整个 Deck 永久学完。
- 弹窗以老师聊天开场，先请学习者用两三句英文总结刚练过的内容；不先展示整块中文场景说明。
- 老师根据用户总结补充关键内容，给出简短、更自然的英文示范，再提出交际任务、双方角色及 2–3 个可用表达。
- 用户明确开始后，老师切换为场景人物进行角色扮演；总结、完善、任务、角色扮演和收尾保留在同一条对话记录里。
- 学习者聊天界面不显示课程/教练副标题或 Recall / Refine / Roleplay 等阶段导航；由老师的对话自然衔接。阶段选择仅保留在开发预览工具栏。
- 以简短英文为主；老师回复、示范、任务及表达的中文默认隐藏，按条点击展开，并可再次收起。
- 场景取自本轮实际练过的卡片、Attempt 内容快照与已有反馈；开始后场景、角色和任务保持稳定。

### Agent 与语音分工

- 保留 pi agent 与受控工具层；独立 Node 服务负责授权上下文读取、场景准备、按需翻译及可选结构化复盘。
- 当前隔离环境试用 `qwen-audio-3.1-realtime-plus`，配套 `loongmary` 音色；通过当前授权 workspace 的 realtime WebSocket 接口调用。使用 Manual 分轮模式，直接接收用户音频、返回文本与语音。模型、音色、endpoint 均为后端配置，不把密钥传给前端。
- 用户点击开始录音，再次点击结束并发送；也可输入简短文字回答。展示双方文字记录并播放 Agent 回复。
- 教学流程只在提示词中约定“引入、角色扮演、结尾”，由模型根据回答自然推进；不实现教学阶段状态机。先作为老师帮助学习者总结和完善表达，再自然切换为场景人物；不逐句打断纠错，听不懂时自然追问。第三人称故事总结有效，不能强行改成用户自身经历。
- 任务完成后自然收尾；最多 8 轮用户发言，用户可提前结束。
- 结束时由 realtime 在聊天里用简短英文自然收尾，不强制再请求一次模型生成报告。独立结构化复盘接口保留为可选能力，含来源引用。中文按已保存的单条消息点击请求 pi 翻译并在当前界面缓存，默认不请求、不显示。仅文本证据不能推断发音结论。

### 数据与权限

- Python API 沿用新模型的会话认证与 CSRF，按认证用户的 Collection 隔离上下文、Dialogue Session、Turn 和 Review；创建时验证当前 Review queue 已耗尽，且提交的已评分 Attempt 集合与本轮完全一致。
- 模型不得决定 user_id / collection_id；pi 通过受控业务工具获取本次授权上下文，不直连 ORM/SQL。
- 持久化对话文字、固定场景与复盘；首版不写长期 memory。
- 保留新 Review / Processing / FSRS 链路；对话记录不作为 Attempt 或 FSRS 评分写入。

### 首版后置

开放式答疑、Markdown RAG、长期 memory、免按键连续对话、自动打断、Dashboard / Library 历史入口。

对话中发现的薄弱点、生词和表达应支持生成卡片草案，展示正反面与来源，用户可编辑、确认或取消；确认后才能调用落库工具，并需去重、变更日志和撤销。该能力已列入后续接入范围，本次模型验证不实现卡片写入工具，不把模型文本同意当成用户确认。

### 验收标准

- [ ] 正常完成一轮后弹出场景窗口；初始空队列、跳过/暂停、请求失败和撤回不误触发。
- [ ] 场景包含原卡片/Attempt 来源，角色与目标在会话内固定。
- [ ] Manual 音频输入、Agent 文字/语音回复和轮次管理可用。
- [ ] 任务完成、8 轮上限和用户提前结束均可获得简短英文收尾反馈，中文默认隐藏。
- [ ] 用户总结之后才出现老师的完善回答；角色扮演在交际任务提出并明确开始之后进入。
- [ ] 老师回复、示范、任务和表达可按条独立展开/收起中文，切换或重置预览后恢复隐藏。
- [ ] 对话与复盘可查询，并隔离不同 Collection；外部 ID 无法越权读取。
- [ ] 网络中断可明确提示并恢复；不把部分回复当成完整发言或伪造反馈。
- [ ] 新 Review / Processing / FSRS 回归检查通过。

- 前端：107 项单元测试通过，类型检查和构建通过；lint 无错误，保留仓库既有的 199 条 warning。
- pi 服务：2 项测试通过，类型检查通过；覆盖真实 pi 工具循环、多请求上下文隔离及 Qwen 的 system 角色与关闭思考模式配置。
- 新模型能力探针通过：服务端回显 `qwen-audio-3.1-realtime-plus`，`loongmary` 音色可用，收到 549,120 字节输出音频，输入转写与工具调用通过。单次合成测试首音频约 1.01 秒，不作为延迟保证；旧 `Tina` 音色不受该模型支持。
- staging 真实模型冒烟曾完整通过（session `01a151be-7460-7837-8326-434cc8b8ffb0`）：两张已评分原卡 → pi 场景准备 → 老师要求总结 → 合成音频复述 → 任务与剧院角色扮演 → 自然完成工具调用；共 5 轮用户发言、3,210,240 字节输出音频。按需中文翻译和可选英文复盘通过，原 Attempt 前后完全一致；自动反馈仍 pending，按真实状态传入。
- 最新收尾修复后的自动回归通过；重复真实冒烟出现两次 pi 场景准备 502（尚未连接 realtime），说明准备链路仍需稳定性排查。此记录不将先前一次成功当作每次都成功，也不将该错误归因于 realtime 模型。合成语音检查不能代替真人对话质量评测。
- 最后一次重跑（session `01a151c5-2b82-7893-bfd3-509af36782a6`）已完成真实语音对话、自然英文收尾与点击翻译；脚本随后在可选 `/review` 请求收到 502，故整条脚本未标记通过。正常 UI 不调用此复盘接口。独立 pi 场景工具循环重测通过，准备/复盘稳定性尚待解决。

- 尚未进行浏览器页面与真人麦克风验收，以上自动检查不替代这两项体验验收。

### 当前上下文接入协议

1. `useReviewSession` 在评分成功后收集本轮 Attempt ID，队列耗尽后提交 `deck_id + review_queue_id + entry_key + attempt_ids`；用户身份从认证会话取得。
2. `practice_context` 核对 Collection、Deck、当前队列及本轮已评分 Attempt 集合。读取 Attempt 的不可变 `note_snapshot / answer_snapshot / input_snapshot`、`asr_result / ai_feedback`、分析状态及评分，按 `card_id / attempt_id` 关联。暂未返回的反馈明确标记 pending，不伪造结果。
3. pi 的 `get_practice_context` 只能读取本次后端绑定的上下文，不接受模型选择用户或直接查库。场景中的目标表达必须引用合法来源并与原文相关。
4. context 原始保存于 DialogueSession（最近最多 40 条且受总长度约束）；实时模型优先获得场景引用的卡片，再获得近期卡片。voice payload 约 26,000 字符，原句/转写/反馈分别裁剪并标明遗漏，原始业务数据不改动。
5. 默认不发送历史用户音频与参考音频，不传媒体对象 key 或签名 URL；当前对话音频直接流入 realtime。历史音频按需核对不属于本次实现，不依据文本声称识别了发音问题。
6. 首次 Start 点击仅生成 provider 的启动控制消息，适配该模型需要 user item 才能开场的限制；该控制消息不作为用户作答保存或计数。重连恢复已保存的完整文字轮次；Finish 点击请求英文收尾。

### 模型验证工具

- `scripts/dialogue/probe_model.py`：合成上下文下检查模型名回显、Manual PCM16 输入/输出、转写和工具调用；从后端环境读取密钥。
- `scripts/dialogue/smoke_session.py`：在独立 backend 内通过真实认证/Note/Card/Attempt/Review API 创建自己的合成练习账号，验证 pi 场景、真实音频与文本对话、按需翻译、可选复盘及练习记录不被修改。不得对预览数据库执行清库测试。
- 回归 pytest 只使用 `lan30_test_*` 临时数据库；预览数据库与该测试库分离。生产服务、数据与模型配置不在本次改动范围。
